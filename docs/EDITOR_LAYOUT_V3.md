# APP-002｜編集画面レイアウト v3・5×5必須語改善

記録：2026-10-19 JST  
正本：`yama-books/crossword-maker`  
変更PR：[PR #21](https://github.com/yama-books/crossword-maker/pull/21)

## 変更理由（iPhone実機の報告）

- 盤面と操作ボタンが上下に大きく離れ、毎回のスクロールが煩雑。
- 必須語「イヌ」「ネコ」（各2文字）等を指定しても、従来の3つの5×5黒マス形状では、入れる語枠すら見つからなかった。
- 新規生成と「残りを埋める」の意味がわかりにくい。後者まで前者の必須語入力を引き継ぐと、現在の盤面と条件が矛盾しやすい。
- 同じ条件で別候補を生成する導線がない。

## 変更後の画面

**スマートフォン**：上から「盤面 → 文字・黒マス・Undo/Redo → 文字入力 → 自動生成/途中補完 → 候補プレビューと採用/別案 → 折りたたみ設定 → 盤面検証とカギ」。他の操作群への長距離スクロールを避ける。

**PC**：左に盤面、右に自動生成、下に盤面チェックとカギ。8bit風のマットボタンや11種類のモーションは維持。

既存の端末内保存キー、編集Draft v2、カナ正規化、JSON入出力、M3a、共通盤面検証、元の問題JSONは変更しない。

## 新規生成と途中補完

- **最初から作る**：新規用の必須語を使用し、登録語のみで完成盤面を探す。現段階では5×5のみ。
- **残りを埋める**：今の盤面（黒マス・入力済み文字）をそのまま固定。**新規用の必須語入力欄を追加制約として持ち込まない**。未入力部分だけ候補を探索する。
- どちらも候補は採用するまで編集盤面に反映しない。
- **別の候補**：新しい探索シードでやり直す。途中で採用しなければ元の盤面は無変更。
- 探索はWeb Workerを使用し、明示中止できる。新規生成の黒マス形状は回転対称・黒マス隣接禁止を保って列挙する。
- 5×5の2語「イヌ」「ネコ」を含む完成解、既存「としょかん・がっこう」のプリセット、辞書の登録語、黒マス・交差条件を自動テストする。

## 留意事項

- 5×5ですべての必須語の組合せが必ず解けるとは限らない。語の長さ、交差、辞書収録、盤面規則で不成立の場合は理由を示す。
- 「探索予算到達」は解が存在しない証明ではない。
- 「残りを埋める」は入力済み文字・黒マスを保護するため、誤入力や未収録の完成語があると成立しない。
- 7×7以上の新規黒マス探索、語単位のロック解除・部分再生成、辞書5,000語義は別タスク。
- GitHub CI / Pages配信とiPhone Safariの実際のタップ、IME・スクロール動作を別の結果として記録する。

## 受け入れ基準

1. UIの盤面近くに編集4ボタン・文字入力があり、その次に新規生成・補完が並ぶ。
2. 5×5、必須「イヌ」「ネコ」の完成問題が `validatePuzzle()` 合格、両語が実際の語枠にある。
3. 従来の「図書館・学校」初期プリセットがそのまま利用可能。
4. 補完時に別モードの必須語制約を黙って強制しない。
5. 再生成（別候補）と採用/Undoが既存編集データを破壊しない。
6. CI成功、Pagesの新HEAD公開、モバイル幅のブラウザで新レイアウトを操作できる。
7. 最後にiPhone Safariで配置・編集・補完を確認し、必要なら修正PRを作る。
