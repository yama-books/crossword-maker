# APP-002｜5×5 必須語プリセット・UI統合計画（2026-10-19）

ステータス：実装ブランチ上の検証計画。PR #18のG1/G2コアに依存し、main/Pagesへの公開は未完了。

## 利用者指定の最初の条件

- サイズ：**5×5**
- 必須語：**としょかん**（正規化後\`トシヨカン\`・5マス）、**がっこう**（\`ガツコウ\`・4マス）
- 難しさ：**むずかしい（3）**
- 辞書：既存の採用語義2,000件（自動公開用には語義・読み・ヒント・カテゴリ・難度のみ）
- 合格：必須2語がそれぞれ**完全な語枠**として入り、他の全語枠も承認済み登録語に一致し、既存\`validatePuzzle()\`が合格。黒マス対称・黒マス非隣接・白マス連結と重複解答禁止は維持。

## 実装ステップ

1. 正本コードから辞書JSON生成・CSP補完を持つPR #18を再利用し、同じロジックを重複実装しない。
2. 制作画面に「必須語」「難易度」と「5×5を自動生成」を追加。利用者指定の2語・難易度3を初期値にする。
3. 語彙JSONの読込と探索を**Web Worker**に移す。中止操作を提供し、編集中の盤面を止めない。
4. 戻り値が\`success\`かつ\`fromPuzzle()\`の全検証が合格した場合だけ、ユーザー承認後に1回のUndo操作として盤面に採用する。
5. \`contradiction\`・\`exhausted\`・\`no_candidate\`は区別し、既存盤面を**一切変更しない**。
6. テストを追加し、PRのCI・Pages buildを確認。iPhone Safariで実際の操作を後日独立に検証する。

## 制約と改善予定

初期G2エンジンは5×5の**候補マスク3種類**を探索する。必須語2つが辞書に存在しても、条件が交差不一致になったり探索上限に達したりするため、必ず完成するわけではない。現在の\`contradiction\`は**試した3形状で見つからなかった**意味であり、5×5全体の数学的な解なし証明ではない。次に全形状探索や複数候補の評価へ拡張する。

- 5×5・必須語2件の「発見できた／できなかった」は、CIの\`USER_PRESET_5x5_DIFFICULT_SMOKE\`ログで観測する。
- 成立しない場合は必須語を無断削除せず、探索形状の追加・ノード上限調整・辞書の偏り測定を先に行う。
- 辞書5,000語義への拡張は別タスク。語数達成自体を完成品質と混同しない。
- 将来の「途中を残して補完」では、黒マス・自作文字・自作語の固定を標準とし、「選択語入替」は同じ補完エンジンで再計算する。
- 現段階のUIは「新規生成」のみ。現行のM3a、Undo/Redo、作業JSONと共存する。
