# クロスワード工房 UI・モーション設計 v1.0

更新日：2026-10-17  
正本：[yama-books/crossword-maker](https://github.com/yama-books/crossword-maker)  
参考：[モーションリファレンス](https://motion-reference.takayustudio.jp/)

## デザイン原則

**既存プレイ画面の清潔感を維持し、マットな8bit携帯ゲーム機の操作感を局所的に重ねる。**

- オフホワイト #F7F8F4、深緑 #2D7460、マットグリーン #E7EEE7、アンバーを使用。
- 本文は読みやすい日本語ゴシックを維持。ピクセル風は硬めの境界、四角い影、短い反応で表現。
- 問題を解く画面と制作する画面を分け、現行の6×6・14問を維持。
- 状態は色だけに依存せず、ラベルや文でも知らせる。

## ブロック型マット凸面ボタン（P0）

**実際に操作可能なHTML button要素**を使用する。飾りだけの箱にはしない。

| 状態 | 動き | 時間 |
| --- | --- | --- |
| 通常 | 2px硬い輪郭、下4pxのマットな立体影 | 静止 |
| ホバー | 輪郭を少し強調 | 約100ms |
| 押下 | ボタンが下へ3px沈み、影は1pxに縮む | 70〜100ms |
| 解除 | 元の位置へ戻る。大きく跳ね返らない | 100〜170ms |
| 無効 | 影と押下を無効化、色を薄くする | 即時 |

実装クラス：編集画面の block-btn / link-btn と、プレイ画面の主要操作ボタン。カギ一覧は装飾を抑える。

## 盤面登場トランジション

1回の盤面切替に1種類を選び、マスごとに異なる種類を無秩序に混ぜない。新規盤面・例題読込・JSON読込・「演出を試す」でだけ再生。**通常の1文字入力では再生しない。**

| ID | 効果 | 表現 | 対象 |
| --- | --- | --- | --- |
| T1 | 右列からスライド | 右から左へ列ごと、列内では各マスに時間差 | 全サイズ・最優先 |
| T2 | マスクワイプ | 端から切り抜きが開く | 11×11以下 |
| T3 | ピクセルディゾルブ風 | 小さく薄いセルが格子へ揃う | 全サイズ |
| T4 | シェイプトランジション | 円形の開口が四角へ展開 | 11×11以下 |
| T5 | 軽いリキッド | 角が一瞬柔らかく変形して戻る | 11×11以下 |
| T6 | グリッドウェーブ | 列・行の順に軽く着地 | 全サイズ |

- 効果はランダム選択し、直前と同じ種類の連続は避ける。
- 12×12以上の盤面ではT1/T3/T6に限定して負荷を抑える。
- 右から左の列遅延は合計約350ms、行内のゆらぎは最大約70ms。セル自身のアニメーションは約400ms。
- 約800ms以内で盤面全体の出現が収束することを目標とする。
- 視覚演出はデータを変更せず、マス入力や保存処理を妨げない。

## 品質・アクセシビリティ

- OSの「動きを減らす」設定を尊重し、prefers-reduced-motionで視覚アニメーションを実質無効化する。
- 盤面の字形、解答番号、カギは演出完了後も同じ。
- 編集失敗・途中保存・完成判定は、動きに頼らず文章で知らせる。
- transform / opacity を主体とし、clip-pathによる複雑な演出は低頻度に限定する。
- 白黒印刷に装飾影は持ち込まず、スマホIMEでもマス編集ができること。
- iPhone Safari、Android Chrome、PCキーボードで押下・日本語入力・復帰・データ保持を実機で確認する。
- 生成アルゴリズムの乱数と演出のランダム性は独立させる。

## v2：盤面演出を11種類へ拡張（2026-10-18）

### #005 中央から上下マスクリビール

[Motion Prompt #005](https://showheyohtaki.github.io/motion-prompt/#005) の中央境界線と上下分割のアイデアを、クロスワード盤面用CSSに翻案。

- 盤面中央のマットなアンバー線が左右へ伸び、上のマス群は下から上へ、下のマス群は上から下へ約720msで収まる。
- 完成盤面はそのまま残し、見せてすぐ編集に戻れるよう、退場アニメーションは採用しない。
- 元のCanvasコードや外部kitは複製・組込みをせず、CSS clip-pathとtransformによる別実装とする。
- 動きの途中でユーザーが盤面をタップ・フォーカスしたら演出を止め、入力を優先する。
- 90度向きを変えた中央左右版、中央アイリスも盤面全体を切り抜く方式で実装する。

### 軽量化・アクセシビリティ

- 121マス超ではセルごとの高負荷マスク／シェイプ／リキッドとアイリスを選択対象から外す。
- src/editor/motion.mjsに演出選択・時間差の計算を集約。乱数で連続同種を避ける。最大時間は850ms以下。
- prefers-reduced-motionの場合は再生しない。印刷時もクリップ・アニメーションを外す。
- 保存・配置成功時は小さなスナップイン、入力違反は左右3px以内のナッジ。大きな跳ねや点滅を避ける。
- ブロックボタンは実HTML buttonで下4pxの硬い影・押下3px沈み込みを維持。

## v2.1：中央リビールの歪み改善（2026-10-19）

ユーザーの実機観察で中央から上下・左右に開く演出が不自然に見えたため、二重の動きを修正。

- **原因仮説**：盤面全体をclip-pathで切り抜くのと同時に各セルを21px/19px移動させ、中央を境にセル位置がずれて見える。さらに案内線をクリップする盤面の内部で描画していた。
- **修正**：盤面を構成するマスと文字の位置は完全に固定し、盤面一枚をクリップする領域だけを中央から対称に拡大する。独立したセル移動アニメーションは撤去する。
- **中央線**：クリップ領域外のboard-stageに描画し、伸長後はフェードアウトする。盤面の表示範囲と案内線のタイミングを揃える。
- **同時編集**：ユーザーのタップ／フォーカス／再生成時には線・クリップ・タイマーをまとめて終了し、マスのイベント処理やデータには影響させない。
- **検証**：HTMLとJSの回帰テストを追加。CI成功とWeb公開は自動検証、iPhone実際の見え方は利用者確認が必要。
