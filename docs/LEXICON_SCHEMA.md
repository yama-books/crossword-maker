# 語彙TSVスキーマ (v1.1)
APP-002 / 2026-10-18

形式: UTF-8 / TSV / 1行1語 / 先頭にヘッダ行 / 改行はLF。セル内改行・タブは禁止。列順は固定。

| 列 | 意味 | 制約・例 |
| --- | --- | --- |
| id | 永続的な語彙ID | LEX-0001。変更や再利用をしない |
| surface | 表示語 | 例: 学校。漢字・通常表記を保持 |
| reading | 通常の読み | 例: がっこう。ひらがな・カタカナ可 |
| normalized | 盤面用文字列 | 例: ガツコウ。現行 `src/core/kana.mjs` の `normalizeKana(reading,{strict:true})` と完全一致 |
| length | 盤面上のマス数 | 正規化後のコードポイント数。2〜15 |
| clue | クロスワード用ヒント | 独自制作。解答語を直接含めない |
| category | 意味カテゴリ | 15の初期カテゴリ。将来拡張可 |
| difficulty | 語彙の難度 | 整数1〜3。カギ文長とは無関係 |
| source | 選定・確認根拠 | 初期: `original_editorial_curation_2026-10-17`。外部照合を行った場合は資料と日付を明記 |
| review_status | 校正状態 | candidate / editor_checked / human_checked |

**互換性:** 既存M3aは「表示名 | よみ | カギ」行をパーサーに渡す方式で、最大60語。辞書をアプリに直接取り込む機能は未実装。将来の連携時は選択した語だけを `surface | reading | clue` の行としてエクスポートでき、`id`・`normalized` 等は辞書内部で保持する。M3aの既存ソースは本PRでは変更しない。

**重複（v1.1）:** `id` は一意。同じ `normalized` を持つ複数の行を**異なる語義・ヒント**として許す。「歌詞」「樫」ならいずれも `カシ`。「表紙」「拍子」ならいずれも `ヒヨウシ`。同じ `normalized + surface + clue` の完全な重複は拒否する。**語彙レコード数と盤面用の異なる答えの数は一致しないことがある。**

**盤面への受け渡し:** `selectOneCluePerAnswer(rows,{difficulty:1|2|3,category:null|string|string[]})` で、指定ジャンル（省略時は全ジャンル）で絞り込んだ後、解答文字列ごとにヒントを一つ選ぶ。 `toLegacyWordList(rows,{difficulty})` は既存の `表示名 | よみ | カギ` 形式を生成できる。選択しなかった語義は辞書から削除されず、別の問題で使用可能。既存のM3aパーサーと盤面生成器は重複した回答文字列を入力としては拒否するため、**この選択処理を経るまで複数語義を直接渡してはならない**。自動辞書接続は別セッションの作業対象。候補ファイルと採用ファイルを両方読み込んで重複入力しない。

**合格条件:** 必須列、正規化一致、許可されたカナ、先頭文字、2〜15マス、IDの一意性、完全同一語義・カギの重複検出、ヒント非空、基本的な答え漏出、状態整合性の自動検査を通す。これにより読み・意味・カギの最終的な自然さが証明されるわけではない。


**辞書からの出題候補出力:** `node scripts/export-lexicon.mjs --category=木の種類 --difficulty=2 --count=12 --seed=42` でジャンル、難易度、マス数を指定して回答の重複を除き、既存M3a向けの `表示名 | よみ | カギ` 形式に変換できる。UIへの自動取込とは別工程。詳細は `docs/LEXICON_EXPORT.md`。


**第6回の確認：** 同一の正規化解答が複数語義を持つ例として、`キル`（着る／切る）、`ハク`（履く／掃く／吐く）、`シリヨウ`（資料／史料）なども許可する。登録レコード数と盤面用ユニーク解答数を別に集計し、ジャンル・難度に応じて語義を選ぶ。
