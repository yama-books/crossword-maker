# APP-002｜UX v4 導線再設計・短押し立体ボタン

日付：2026-10-20 JST  
対象：`yama-books/crossword-maker`  
根拠：iPhone Safari実機からの「何をすべきかわからない」「ボタンは長押ししないと沈まない」という報告

## 変更方針

1. 最初から全ツールを見せず、**ことばから作る／自分で作る**の2択へ。
2. ことばから作る場合は「入れたいことば」1行1語と作成ボタン、結果プレビューに集中。不要な黒マス・サイズ・カギの設定を表示しない。
3. 自分で作る場合は編集盤面を最初に表示。入力・黒マス・Undo/Redoと「空いているマスを自動で埋める」を盤面の近くに置く。
4. 生成された完成候補は**採用して編集する**で初めて既存の編集データへ反映する。既存のUndo履歴・localStorage保存を維持。
5. 生成に失敗した場合、探索数・実装上のステータスよりも次の操作を提示。「ことばを1つ減らして試す」ボタンを用意する。**不成立と探索上限到達は内部的には引き続き区別**。
6. 旧M3a単語交差配置、アニメーション、手動盤面サイズ、カギ、JSONは削除せず編集画面の詳細メニューに保持。

## 実装ファイル

- `editor.html`：開始画面、3つの状態（welcome / words / editor）、再開・戻る導線、採用・失敗時リカバリー
- `src/editor/ux-v4.css`：状態別の単純化、モバイル向けウェルカムカード・ボタン
- `src/editor/app.mjs`：画面遷移、既存保存データの継続、簡単なエラーメッセージ、近接した部分補完操作
- `scripts/build.mjs`：公開HTMLと同じ場所にv4 CSSを配置
- `tests/ux-v4.test.mjs`：導線・自動保存・初期語空欄・短いタップの押下処理を回帰検証
- 旧v3・必須語プリセットのUIアサーションは新UIに整合。**生成計算そのものの既存テストは維持**。

## 短押しで沈むボタン

従来はCSS `:active` の可視区間が短く、iPhoneで「長押ししないと沈まない」と感じられた。

- `pointerdown` 直後に `.is-pressed` を追加。CSSで移動5px、底面影を消し、明るさもわずかに変える。
- `pointerup` 後約120ms、短押しの視覚表現を保持。
- `pointercancel`・`blur` で解除。Enter/Space入力にも対応。
- `touch-action:manipulation` を設定し、クリック処理の発火自体は妨げない。
- 実機確認前に「iOSで確実に動作」とは断定しない。Safariで軽いタップ／連打／スクロール時の誤反応を確認する。

## 保存と互換性

端末内の保存キー `jp-crossword-maker-draft-m2` とdraft v2は変更しない。前回のデータがあるときのみ「前回の続きから」を表示。アプリの起動時は新ホームを示すが、自動保存データは**初期表示するだけでは消去しない**。

## 制約と次段階

- 完成問題の新規自動生成は**5×5のみ**。UX v4が自動的に7×7・9×9へ広げるわけではない。利用者には「まず5×5で探す」と明示。
- 高難度・3語以上の必須語では探索上限・構造制約で失敗しうる。新しい誘導操作でも数学的な解無しを証明していない。
- 選択語だけの入替、語単位ロック、辞書5,000語への拡充は後続開発。
- 初回UX v4の最優先テストは、**iPhone Safariで短くタップした瞬間にボタンが沈むか**と、新規利用者が説明無しに初回のクロスワードを生成できるか。

## 検証基準

- welcome → words → 5×5完成候補 → 採用 → editor → Undo
- welcome → editor → 手入力 → 残りを埋める → 採用 → Undo
- 過去に入力済みの作業が残っている場合、welcome → 前回の続きからで復元
- 生成に失敗した場合、入力値・保存盤面を消さずに「ことばを1つ減らして試す」へ進む
- CSS押下状態はpointerdownですぐ発火し、pointerupで短時間だけ保持され、pointercancelで解除
- 既存の解く画面・14問と辞書・生成エンジン・JSON出力が回帰しない
- CI成功と公開Pages確認、スマホ向けブラウザ操作、**iPhone Safari実機**をそれぞれ別の成果として記録
