# M1 基盤整備・実装メモ

更新: 2026-10-17  
作業ブランチ: work/m1-validation-20261017  
正本: https://github.com/yama-books/crossword-maker

## 実装の目的

M1では「検証可能な一つの問題データ」を作る。既存6×6・14問のプレイ画面を変更せず、単語とカギを編集した際のデータ不一致をCIで阻止する。

## 変更点

- **正本JSON**: \`puzzle.json\` のみ手動変更する。従来通りの問題スキーマを維持。
- **プレイヤーのテンプレート**: \`src/index.template.html\` でHTML/CSS/操作UIを管理。
- **入力正規化**: \`src/core/kana.mjs\` から全角カナ・小書きカナ処理を生成HTMLに埋め込み、単体テストとブラウザ操作が同じコードを参照。
- **盤面解析**: \`src/core/puzzle.mjs\` の \`extractSlots()\` が横/縦の連続白マスと開始番号を抽出。
- **検証**: \`validatePuzzle()\` はタテ・ヨコ、交差、漢字混入、黒マス隣接、白マス分断、単語の重複、開始文字、ヒント、座標/番号を調べる。
- **配布**: \`npm run build\` が検証済みの \`dist/index.html\` を生成。
- **CI/CD**: PRに対してテストし、mainへマージ後は同じ検証を通ってGitHub Pagesへ公開。

## 更新ルール

1. 新しい問題を作る場合はまず \`puzzle.json\` の構造とカギを編集。
2. テスト・正規化・プレイヤーテンプレートも必要に応じて更新する。
3. \`npm run sync\` でオフライン用の \`index.html\` を生成。
4. \`npm test && npm run check && npm run build\` を成功させる。
5. PRで変更内容と検証証跡をレビューしてマージ。
6. GitHub Pagesの公開をActionsの成功・実際の表示で確認する。

*GitHub Webエディターだけでも問題データ編集は可能。ただし生成HTMLの同期が必要なので、将来的にはGitHub Actions上でソースから自動作成し、成果物を直接配布する運用へ整理する。*

## 自動検証の限界

- 辞書や参考文献を参照した語義チェック、カギの品質レビューはまだ行わない。
- 新規盤面の自動生成は未実装。
- 編集画面・Word/PDF出力などは後続のM2以降。
- 標準ルールは比較的厳格（黒マス連続禁止・180度対称）。例外は \`ruleSet\` または関数のオプションで切り替えられる。
