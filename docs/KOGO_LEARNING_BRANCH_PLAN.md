# APP-002 分岐機能｜古語クロスワード（古典学習モード）構想 v0.1

作成：2026-10-20 JST  
状態：**採用方針・構想設計。未実装。**  
正本候補：既存の `yama-books/crossword-maker`。新規リポジトリ作成・Web公開は行わない。  
関連：APP-015 古語Wordle、APP-007 古典学習帳（互いの責任範囲は維持）。

## 1. 決定した位置づけ

ユーザーは「古語クロスワード」を**クロスワード工房 APP-002 から派生する機能**として育てたい。新規アプリを別々に複製するのではなく、APP-002 の一般クロスワード機能・盤面生成・編集・解く画面を再利用し、その上に**「古典学習モード」**を増設する。URL短縮・クラウド共有基盤は今回の対象外。

仮称は「古語クロスワード」。扱う学習内容は狭義の古語だけでなく、古典作品の本文、語義、文学史、文法、時代背景まで含む。「古語を答える」ことだけに限定しない。

## 2. 出題の核心：解答語とカギを分離する

同じカナ解答に対して「一般の説明」「古典作品に基づく問い」「語義を問う問い」など複数のカギを登録し、生成時に選択する。

**例（教材採用前に本文・語義・表記・既存辞書との照合が必要）**

| 解答カナ | カギの例 | 問いの分類 |
| --- | --- | --- |
| ヨル | 『枕草子』の「夏は〇〇」。〇〇に入る言葉 | 作品の本文・古典関連の現代語 |
| アケボノ | 『枕草子』の「春は〇〇」。〇〇に入る言葉 | 本文・現代語 |
| ヲカシ | 「趣がある」「興味深い」などを表す古語 | 古語そのもの |
| タイクツ | 古語「つれづれなり」の意味。〇〇〇〇だ | 語義・現代語 |
| トテモ | 古語「いと」の意味の一つ。「〇〇〇」 | 語義・現代語 |

既存辞書に未収録の解答は、レビューを経て補う。歴史的仮名遣い・音便・小書きカナの盤面正規化を別々に管理する。文字数はクロスワード上の正規化後のカナ数を使う。

## 3. 問題バンクのデータ設計（案）

現在の `data/lexicon/approved_lexicon.tsv` は解答候補を保持する基盤として残す。**古典用のカギは別ファイル**に追加し、一般語彙のカギを上書きしない。

例えば `data/learning/kogo_clues.jsonl` の1件に以下を持たせる。

- `clue_id`：安定した問題識別子
- `answer` / `answer_key`：クロスワード用に正規化した解答／既存語彙への参照
- `prompt`：盤面で実際に表示するカギ（丸数字等の曖昧な空欄を避ける）
- `question_type`：`classical_word`（古語解答）／`modern_meaning`（現代語義解答）／`passage`（作品本文）／`literary_history`／`grammar` など
- `difficulty`：易・標準・難。語自体の難しさと**カギの難しさを分離**
- `classics_related`：古典関連の設問かどうか
- `work`、`source_reference`、`source_excerpt`：出典・本文位置・根拠の短い記録
- `explanation`：正答後の解説。解答前に正解の漏えいを防ぐ
- `review_status` / `review_note`：未校閲・採用可能・差戻し等
- `curriculum_tags`：作品・学年・学習単元等（内部の学校情報や生徒情報は記録しない）

古語の見出し語、実際の解答カナ、出題文は別概念とし、「枕草子」という作品名と答えの語を混同しない。

## 4. 出題割合は2軸で制御

- **古語を解答する割合**：解答語が狭義の古語である枠の割合。
- **古典に関連するカギの割合**：一般語を答えても『枕草子』や古語の意味を出題するものを含む割合。

上記の2軸は独立。例えば「古典関連70%、古語解答25%」なら、残りは一般的なカナ解答でも古典由来の問いを選べる。これは**目標比率**であり、全語枠の成立・辞書照合・交差条件の適合を優先する。達成した実数を完成画面に表示する。

難易度は「やさしい・ふつう・むずかしい」を初期案とする。説明文の難しさと知識量、ヒントの有無を別々に扱う。

## 5. 体験・授業の使い方

- 既存の「ことばから作る」「自分で作る」を破壊せず、作成・プレイ開始時に**通常／古典学習**を選べる導線を検討。初回に高度な配分設定を並べない。
- 古典学習モードは「単元・難しさ」を選び、あとは1つのボタンで作成。解いた後に語義や作品の解説を表示。
- 生徒側は全問正解までの所要時間、正誤・ヒント回数を確認できる。記録は問題ID・問題版と紐づける。
- 最初の教材運用は端末内計測と結果テキストのコピー/提出で試す。偽装可能な自己申告の記録を厳密な成績評価に使わない。学校の認証・生徒情報収集・サーバーへの提出・ランキングは**別途の設計・承認が必要**。
- 長い共有URLや短縮URLの新規開発は、この分岐モードの着手条件にしない。既存の共有・JSON機能を可能な範囲で使う。

## 6. 既存コードとの境界

- **共通基盤**：`src/core/puzzle.mjs` の盤面抽出・ルール検証、`src/generator/auto-fill.mjs` の生成器、`src/editor` とプレイヤーは極力共有。
- **新規領域（将来）**：古典カギの語彙インデックス、教科モード用選題ポリシー、難度配分、解説表示、時間計測は `src/learning/kogo/` 等に分離。
- **混在回避**：古典の問題バンクを既存辞書のカギ欄に直接上書きしない。一般クロスワードも引き続き独立して使える。
- APP-015（古語Wordle）やAPP-007（古典学習帳）から共用するのは校閲済みの語彙・出典管理スキーマ等に留め、既存機能の無断移管・統合は行わない。

最初の一歩は**K1の30題試作**。語数の拡充より、同じ語に複数の良い古典的カギを持たせることを優先する。規模を無理に増やして過剰校閲にならないようにする。
