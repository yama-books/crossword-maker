## 1. 決定した位置づけ

ユーザーは「古語クロスワード」を**クロスワード工房 APP-002 から派生する機能**として育てたい。新規アプリを別々に複製するのではなく、APP-002 の一般クロスワード機能・盤面生成・編集・解く画面を再利用し、その上に**「古典学習モード」**を増設する。URL短縮・クラウド共有基盤は今回の対象外。

仮称は「古語クロスワード」。扱う学習内容は狭義の古語だけでなく、古典作品の本文、語義、文学史、文法、時代背景まで含む。「古語を答える」ことだけに限定しない。

## 2. 出題の核心：解答語とカギを分離する

同じカナ解答に対して「一般の説明」「古典作品に基づく問い」「語義を問う問い」など複数のカギを登録し、生成時に選択する。

**例（教材採用前に本文・語義・表記・既存辞書との照合が必要）**

| 解答カナ | カギの例 | 問いの分類 |
| --- | --- | --- |
| ヨル | 『枕草子』「夏は〇〇」 | 作品の本文・古典関連の現代語 |
| アケボノ | 『枕草子』「春は〇〇〇〇」 | 本文・現代語 |
| ヲカシ | 「趣がある」の古語、〇〇〇 | 古語そのもの |
| タイクツ | つれづれなりの意味、現代語で「〇〇〇〇だ」 | 語義・現代語 |
| イト | 『枕草子』「霜の〇〇白きも」 | 古語を答える（語義注記付き） |
| タイヘン／タイソウ | 古語「いと」の意味、現代語で〇〇〇〇 | 語義・現代語（同義訳の扱いを記録） |

既存辞書に未収録の解答は、レビューを経て補う。歴史的仮名遣い・音便・小書きカナの盤面正規化を別々に管理する。文字数はクロスワード上の正規化後のカナ数を使う。

## 3. 問題バンクのデータ設計（案）

現在の `data/lexicon/approved_lexicon.tsv` は解答候補を保持する基盤として残す。**古典用のカギは別ファイル**に追加し、一般語彙のカギを上書きしない。

例えば `data/learning/kogo_clues.jsonl` の1件に以下を持たせる。

- `clue_id`：安定した問題識別子
- `answer` / `answer_key`：クロスワード用に正規化した解答／既存語彙への参照
- `prompt`：短いクロスワード型のカギ。〇の数は正規化した解答のマス数と一致させる
- `question_type`：`classical_word`（古語解答）／`modern_meaning`（現代語義解答）／`passage`（作品本文）／`literary_history`／`grammar` など
- `difficulty`：易・標準・難。語自体の難しさと**カギの難しさを分離**
- `classics_related`：古典関連の設問かどうか
- `work`、`source_reference`、`source_excerpt`：出典・本文位置・根拠の短い記録
- `explanation`：正答後の解説。解答前に正解の漏えいを防ぐ
- `review_status` / `review_note`：未校閲・採用可能・差戻し等
- `curriculum_tags`：作品・学年・学習単元等（内部の学校情報や生徒情報は記録しない）

古語の見出し語、実際の解答カナ、出題文は別概念とし、「枕草子」という作品名と答えの語を混同しない。

## 4. 出題割合は2軸で制御

- **古語を解答する割合**：解答語が狭義の古語である枠の割合。
- **古典に関連するカギの割合**：一般語を答えても『枕草子』や古語の意味を出題するものを含む割合。

上記の2軸は独立。例えば「古典関連70%、古語解答25%」なら、残りは一般的なカナ解答でも古典由来の問いを選べる。これは**目標比率**であり、全語枠の成立・辞書照合・交差条件の適合を優先する。達成した実数を完成画面に表示する。

難易度は「やさしい・ふつう・むずかしい」を初期案とする。説明文の難しさと知識量、ヒントの有無を別々に扱う。

## 5. 体験・授業の使い方

- 既存の「ことばから作る」「自分で作る」を破壊せず、作成・プレイ開始時に**通常／古典学習**を選べる導線を検討。初回に高度な配分設定を並べない。
- 古典学習モードは「単元・難しさ」を選び、あとは1つのボタンで作成。解いた後に語義や作品の解説を表示。
- 生徒側は全問正解までの所要時間、正誤・ヒント回数を確認できる。記録は問題ID・問題版と紐づける。
- 最初の教材運用は端末内計測と結果テキストのコピー/提出で試す。偽装可能な自己申告の記録を厳密な成績評価に使わない。学校の認証・生徒情報収集・サーバーへの提出・ランキングは**別途の設計・承認が必要**。
- 長い共有URLや短縮URLの新規開発は、この分岐モードの着手条件にしない。既存の共有・JSON機能を可能な範囲で使う。

## 9. K1試作30題と「古語の意味は注意深く扱う」恒久原則（2026-10-20）

**最優先ルール：古語の訳語を短い現代語1語へ機械的に固定しない。** 意味の幅・本文の前後関係・品詞・打消しとの共起を確認してからカギに採用する。

1. **文脈を固定する**。古語の意味を問う場合は「どの作品のどの箇所」か、必要なら該当する短い本文や使用状況を示す。辞書の複数義を混ぜて別の用例へ使わない。
2. **「いと」は指定訳を優先**。程度の強調で肯定文の例では「**たいへん／たいそう**」を主要な説明・模範訳とし、「とても」を自動的に唯一の正解へしない。ただし辞書上ほかの訳が存在することも記録し、打消しを伴う用法の「それほど～ない」と混同しない。
3. **複数正答への対処（K2改訂）**。「いと→たいへん／たいそう」などを排除せず、中心義と許容訳語を併記する。クロスワードの盤面上は交差から1つの語形が決まるが、他方も意味として正しいと表示し、自由記述型の評価では許容する。解答文字数による意図的な語形指定も選択肢だが、空欄記号の個数で一律に示さない。
4. **「つれづれ」等も多義を保持**。『徒然草』冒頭の手持ち無沙汰・所在なさは「退屈」と説明できるが、他の用例で物寂しさ等を表すことがある。一般的な「つれづれ＝退屈」だけを無条件に全用例へ当てない。
5. **歴史的仮名遣いと読みを分離**。「をかし」「あはれ」「やうやう」は古典表記を保持。正解判定で歴史的仮名遣いを要求するモードと、現代発音に合わせるモードを混同せず、読みの正規化で消える区別を記録する。
6. **漢字・同音異義語は意味一致を確認**。「いと／糸」「けんこう／健康」「くも／蜘蛛」は読みが一致するだけで既存辞書へリンクしない。照合は解答カナだけでなく、原語の語義・作品の用法・表示語が対応するものだけ。
7. **正答と解説を分離**。解答前のカギに答えの文字列を意図せず露出させない。解答後の解説に本文・典拠・語義の注意点を記載する。
8. **出典を残す**。出典のない創作・現代風の説明を原典の引用として扱わない。本文の異同や不確かな意味は `hold` にして教材・自動生成への採用を止める。本文確認と辞書確認を分けて記録する。
9. **レビューは必要十分に**。原典の確かな穴埋めは本文1資料、意味の揺れる語は辞書・用例を追加で確認。全件に無限の校正を重ねず、不確かな設問にレビューを集中させる。
10. **確定の境界**：問題バンクの `source_checked_candidate` は原典照合済みの試作段階であって「授業採用済み」ではない。自動出題は教員の校閲を経た `human_checked` のみを許可する。 `hold` は一律出題禁止。

## 10. K2 重要方針改訂｜中心義で積極的に出題する（2026-10-20）

**旧方針の「多義語・別解のある設問は採用保留」を廃止する。** 多義語は古典学習の核であり、一般的な辞書の筆頭義・基本義・教材で優先する中心義を教え、必要な場合には用例・本文を添える。危険な意味の誤りと、妥当な複数訳語の存在を区別する。

1. **中心義から出題**：まず代表的な辞書の見出し語の第一義や、教科教材としての頻出中心義を指定する。辞書によって義順が異なる場合は「どの辞書のどの語義か」を `dictionary_reference_url`、`target_sense` に残し、単一の辞書の番号を普遍的な正解としない。
2. **問いの種類を増やす**：単語の中心的な意味を答える、本文中の意味を答える、意味の説明から古語を答える、原文の空欄を埋める、適切な現代語訳を選ぶ、という複数の問い方を許可する。用例が不要な問いに原典引用を強制しない。
3. **多義語を教材から外さない**：正解候補が複数ある場合、`meaning_group_id`、`meaning_policy`、`target_sense`、`acceptable_answer_readings` に正しい表現群を登録する。盤面には1つの文字列を採用して交差させるが、別の妥当な訳語を意味の誤りとは扱わない。自由入力での同義答の自動採点は今後の学習UIで対応する。
4. **「いと」は肯定の中心義を問える**。「たいへん」「たいそう」を代表訳にし、双方を許容。打消しと呼応して「それほど…ない」などになる文脈では別の `meaning_group_id` を使う。現代語の答えを一つだけ強制するために、誤った限定説明をしない。
5. **「つれづれなり」は中心義を重視**。『徒然草』の冒頭では「することがなく、所在ない／手持ち無沙汰である」が中心。「退屈だ」も学習しやすい言い換えであり、正しい表現として保持する。別義の「物寂しい」は正答後の補足や高難度の文脈問題へ。
6. **空欄の記号は文字数を表さない**。「〇〇」「（　）」を正解カナ数と一致させる必要はない。読みやすさのため本文穴埋めの標準は**「（　）」**とし、文字数は盤面のマスから分かる。特定の授業意図があるときのみ「四文字で」などと明示できる。単なる空欄記号の数を検証器で数えることは禁止。
7. **止める条件は意味の誤りがある場合に限定**：原文が誤り・辞書と意味が一致しない・学習上の誤解を強く招く・適切な解答が作れない場合は `hold`。多義性そのものや、歴史的仮名遣いを要求する出題形式であることを理由に自動的に `hold` としない。
8. **校閲は過剰にしない**：出典と一貫した解答語・中心義を確認したら試作候補にする。曖昧なもののみ重点チェック。試作候補を学生に自動出題するのは、引き続き教員の最終承認後とする。

## 11. K3 正式決定｜クロスワードらしい短いカギ・文字数一致（2026-10-20）

**この節が現在の正本。第9・10節にある「（　）」の一定幅表記・空欄の数と解答文字数を対応させない規則は撤回した。**

- **〇を使う**：盤面のカナ正規化後の解答1マスにつき「〇」を1つ置く。小書き仮名は盤面規則上1つの大きなカナになるため、正規化後の文字数で数える。
- **短く自然に**：『枕草子』「夏は〇〇」、つれづれなりの意味、現代語で「〇〇〇〇だ」、古語「いと」の意味、現代語で〇〇〇〇。句読点や鉤括弧は読みやすさを優先。
- **不要な説明を取り除く**：「〇〇に入る言葉」「中心的な意味を答えよう」「空欄を埋めてください」など、クロスワードとして自明な指示は書かない。
- **意味の厳密さは内部データへ**：`target_sense`、`meaning_group_id`、`acceptable_answer_readings`、`explanation`、`source_url` に保持する。問題文は短くても古語の意味を誤って示さない。
- **多義語は出題可能**：代表的な語義を普通に問う。必要なときは作品名や短い引用で絞り、妥当な別解は内部に保持する。『いと』の訳は「たいへん／たいそう」を優先。
- **本文穴埋めは出典と一致**：もとの作品の語句を取り違えない。本文の版による表記差を `review_note` に残し、不確実なもののみ `hold` とする。
- **校閲負荷を適正に**：機械的に〇の数、ID、読み、出典、重複、データ構造を確認し、意味は初稿・最終教員校閲の2段階で判断する。全件で過剰な調査をしない。

### 66題への増補とCHECKPOINT

- 旧30題すべてを上記の短いカギへ修正し、**36題を追加して合計66題**。
- 対象は『枕草子』26題、『徒然草』10題、『方丈記』10題、『竹取物語』9題、『平家物語』6題、『源氏物語』5題。
- 代表的な新規出題：『竹取物語』「うつくし」の意味、〇〇〇〇 → カワイイ。現代語「美しい」と取り違えない（参考：静岡県あすなろ学習室）。
- 新規出典は古典本文・公的教材・典拠の明確な校訂資料を優先した。新しい36件は意味照合が完了するまで既存語彙に自動リンクしない。
- **66題は教材候補であり最終承認済みではない**。`source_checked_candidate` と `hold` の区別は維持し、`human_checked` への無断昇格をしない。
- `scripts/check-kogo-clues.mjs` はすべての問題で `circle_count === [...answer].length`、問題文の実際の「〇」個数一致、説明的な言い回しの抑制を確認する。
