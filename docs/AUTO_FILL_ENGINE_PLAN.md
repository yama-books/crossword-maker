作成：2026-10-19 JST

対象：M3b（辞書接続＋自動充填）、M4（自作盤面の部分補完）、M5（語入替・範囲再生成）、L2（語彙5,000語義）

## 0. 利用者が得たい体験

以下を**一つの共通エンジン**で実現する。

1. **最初から生成**：「としょかん」「がっこう」など、必ず入れたい語を0〜数個指定し、残りを辞書から埋めて、完成した盤面を複数案提示する。
2. **途中から完成**：自分で文字、語、カギ、黒マスを編集し、「残りを自動で埋める」で補完する。自作内容を無断で変更しない。
3. **特定語の入替**：盤面中の語を選び「別の言葉に」を実行する。原則、その語枠と非保護の交差語だけを再探索する。固定内容を守れなければ結果を採用せず、理由と選択肢を表示する。

既存のM3a「入力語の交差配置」は残すが、**配置案と完成問題を明確に分ける**。完成とは全語枠に出典管理された語または作成者承認語が入り、標準盤面規則とカギの検証を通過したものをいう。

## 2. 統一した入力モデル

```js
{
  rows, cols,
  mode: "new" | "fill" | "replace",
  grid: [...],             // 編集時点の白黒・入力済み文字
  fixedCells: [...],       // [r,c,value]。値は文字、または黒マス
  fixedSlots: [...],       // [direction,r,c,answer,clue?]。作成者が保持を指示
  requiredAnswers: [...],  // 語の文字列、辞書ID/作成者語IDを解決後に正規化
  editableSlots: [...],    // replaceの対象・影響を受けてもよい語枠
  preserveBlackPattern: true,
  dictionaryFilter: {difficulty, categories, discoveryLevel},
  seed, maxNodes, maxMillis, maxSolutions
}
```

- マス単位と語枠単位のロックを区別する。**自分で書いた語・黒マスは初期値で保護**、利用者が明示解除したものだけ探索対象とする。
- 「途中まで自作」の白マス未入力はワイルドカード扱い。作成者自身の辞書未収録語も固定可能とし、独自のカギを要求する。
- 固定語の交差文字が矛盾する場合、計算に入る前に対象マスを示す。
- 入替の基準は確定した「カギ・解答枠」とする。1マスだけの置換や、固定交差を破壊する操作は行わない。
- `requiredAnswers` は結果のヨコ/タテの**実際の語枠**に含まれなければならない。途中文字列の偶然の一致は不合格。
- 同じ読みで異なる語義が複数ある場合、**同一問題で同じカナ解答は原則1回**。辞書には全語義を残し、候補ごとに一つのカギを選ぶ。

既存draft v2を壊さず、後方互換の任意`locks`/`generation`追加を検討。保存形式変更が必要ならバージョンアップと移行テストを必ず実施する。

## 3. 生成エンジンの構成

```text
UI（新規／途中補完／入替）
    ↓ 明示的な保護・必須語・好み・タイムアウト
normalizeGenerationRequest()
    ↓
board-shape 探索（新規のみ）／既存黒マス固定（途中補完・入替）
    ↓ 語枠抽出・対称性・連結性・長さと固定文字の検査
candidateIndex（辞書読みの長さ＋位置文字インデックス）
    ↓
CSP solver（MRV + forward checking + backtracking + seed付き順序）
    ↓ 交差完全一致／必須語維持／重複禁止
validatePuzzle() ＋全語枠の語彙ID/作成者承認語確認
    ↓
候補の評価・プレビュー（採用前は元の編集盤面を変更しない）
    ↓ ユーザーが選択して採用 → 1つのUndo単位 → JSON自動保存
```

### 3.1 生成モード

- **新規生成**：まず既定ルールで成立する候補黒マス配置を作る。固定した必須語を置ける方向・長さを検査し、全語枠を辞書で埋める。初期は5×5・7×7を対象、9×9以上は性能を検証した後で解放。
- **部分補完**：黒マス配置を固定し、既存の確定文字・語・カギを保護して**未確定語枠のみ**を埋める。固定文字列と辞書候補が一致しなければ代替案を示す。
- **語入替**：対象語を変更可能にし、影響範囲内の非固定語も再探索。隣接の変更を許す範囲は「その語だけ」「交差語を含む」から選べるようにする。解けない場合は元の盤面に戻したまま、「交差語を追加で解除」「別位置の語に変更」など説明する。

### 3.2 計算量・停止条件

- 候補語数と交差制約により探索は指数的に増大し得る。ノード数・再起動回数・壁時計時間に**必ず上限**を設ける。
- ブラウザのUIスレッドを塞がないようWeb Workerに計算を分離する。中止・進行率は実測ノードと経過で示し、根拠のない完成率%は表示しない。
- 同一辞書バージョン・seed・条件のときは再現可能な候補順を基本とする。
- **結果種別**を `success`、`contradiction`（論理的制約衝突）、`exhausted`（探索上限）、`no_candidate`（該当語なし）、`cancelled` で分離する。
- `success`でもヒントの自然さは人間確認を求める。全条件に合致する候補が得られなければ「完成」と表示しない。
- 求解精度を確認するため、ロック0/複数、既知の成立盤面、矛盾盤面、長い語、同音異義の回帰ケースを用意する。

## 4. 辞書5,000語義への拡張

**推奨：5,000語義を中期目標とし、生成可解性を優先して段階的に拡張。** 2,000 → 3,000 → 4,000 → 5,000 と増やすが、語数達成だけを品質完了としない。

- 語彙の長さ別分布、交差文字出現、詰まりやすいパターンを集計して必要な語を補う。特に短語・5〜8マス語の使いやすさを計測する。
- 「身近な語」「ちょっと知らない語」「思いがけない発見がある語」を併存させる。**難しい語を機械的に除外しない**。
- 各語に `difficulty`（語の難度）に加えて、将来 `familiarity`/ `discovery`（珍しさ・学びの面白さ）や`theme`を付与可能にする。既存スキーマを壊さず段階導入。
- 生成時は標準：身近な語を主体、少し難しい語を少数混ぜる。任意で「発見を多めに」を選べるようにする。これは目標比率であり、全語枠・必須語制約を優先する。
- 解答表示後に「この語、知っていましたか？」から意味や補足を見られる将来UIを検討。**解答前に答えが漏れる表示はしない**。
- 自然な日本語の実在・品詞・読み・意味・カギの根拠を確認し、外部辞書の無断転載をしない。
- 同音異義語の複数カギを積極的に残す。交差による推理が成立すればカギ単独の一意性は必須でない。

## 5. UI案（段階導入）

1. 編集画面に「自動でつくる」「残りを埋める」「選んだ語を入れ替える」の3操作を追加し、すべて一つの生成パネルを使う。
2. 操作前に「この語／黒マスを守る」というロックを可視化。特にユーザーの編集済み部分はデフォルトで保持する。
3. 生成候補を最大3件提示：必須語採用数、全語枠成立、難語、変更された箇所、未変更の固定マス、探索上限を明示。
4. 「採用」で編集状態を一つのUndo単位で保存。候補を見るだけで元の盤面を書き換えない。JSONにはseedと辞書バージョン・保護情報を残す。
5. スマホ：生成中のフリーズを防止。結果は縦並びカード、どのマスが変わるか盤面プレビューで比較。

## 7. 追加受入テスト

- 必須語2語の指定で、両方が最終的な語枠に含まれ、全カギが紐づき、正本の検証が成功する。
- 完成した固定例題の半数の語を外して再補完した際、**ロックされた文字・カギ・黒マス**が元の値と完全一致。
- 互いに矛盾する2つのロック語は適切に失敗し、draft、Undo履歴、保存済みJSONは無変更。
- 語枠の入替で、他の固定語を1文字も変えない。生成不成立なら無変更のまま理由を出す。
- 辞書の同音異義語は残り、同一盤面では同じ解答を重複配置しない。
- 生成中のキャンセル、5×5と7×7、低速端末、離脱/再訪、JSON復元が正常。
- 出力可否は必ず既存の`validatePuzzle()`に連動し、未完成や制約違反は完成問題JSONを出せない。

## 8. 決定／未決

**今回の方針として採用**：新規自動生成、途中補完、単語入替を一つの制約充足エンジンに統合。必須語・自作内容の保護を最優先。未知語に出会える体験を活かす辞書拡充を検討する。

**実験で決める**：5×5/7×7の平均成功率と上限時間、黒マス自動候補の種類、難語混合比率、9×9/15×15の性能、5,000語義到達の所要作業量。
