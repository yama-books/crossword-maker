# APP-002 語彙のブラインド実解テスト：第1回

更新：2026-10-18 / 2,000語義初稿から抽出

## 目的
機械検査ではわからない「ヒントを読んだとき本当に意図した答えが浮かぶか」を確認する。特に、**同じ意味で異なる読み**を持つ語（例：ものさし／定規）を重点的に調べる。**同じカナで異なる意味**（樫／歌詞など）は辞書内に併存させる方針であり、削除しない。

## 用意したもの
- [回答者へ渡す40問（答えなし）](LEXICON_REVIEW_R1_QUESTIONS.md)。スマートフォンでそのまま読め、10問単位で区切って実施してもよい。
- [採点者用の答え・語義ID一覧](LEXICON_REVIEW_R1_KEY.md)。**回答者には見せない**。公開リポジトリ内のページなので、直接リンクを渡さず問題用紙だけ配布する。
- `node scripts/prepare-lexicon-review.mjs --questions` / `--key` でTSVから再生成できる。並び順は固定してある。

## 手順
1. 回答者にはヒントと盤面マス数だけを見せ、辞書・正答表を見ないでもらう。ジャンル情報も初回は伏せる。
2. 回答、迷い、別解、確信の高さを記録する。無理に当ててもらわず、不明は空欄でよい。
3. 採点者が解答と比較し、**同義語で別解が出た場合には回答者の誤りではなく、カギの改善候補**として集計する。
4. 問題番号ごとに解答数、正答数、別解の内容、難しさの感想を記録。必要ならヒントを改訂し、改訂後に別の回答者で再試験する。
5. 回答者の氏名・連絡先や個別の生データは**公開GitHubへ掲載しない**。人数・件数・匿名化した別解の集計だけにする。

## 判定の目安（暫定・合否の固定閾値ではない）
- 意図した読み以外が自然に複数出るなら「カギ要修正」とする。意味の近い語義を辞書ごと削除する必要はない。
- **同じカナの異義語**は、一問の中でカギ一つに絞る現在の仕組みを維持する。
- 少なくとも数人の別々の回答者で再現した結果を評価する。実解がない現時点では `editor_checked` のままで、`human_checked` は付けない。
- 誤答が少なくてもヒントや読みが事実に反すれば改訂する。

## 既知の注意点
文面の類似率だけで自動的に不正扱いはしない。「北東／南東」のように方角で明確に識別できるものは保持する。一方、同じ用途の用具・似た食品名など、**答えの文字列が異なるのに同じカギが通る**組み合わせを優先して検査する。

初回の40問は編集上の試験問題であり、実際の回答者の採点結果はまだ存在しない。
