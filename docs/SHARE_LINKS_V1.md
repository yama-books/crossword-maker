# APP-002｜解く画面を共有する｜v1（2026-10-20）

## 目的

完成したクロスワードを「問題を共有する」からURL化し、受信者がログイン不要で解けるようにする。GitHub Pagesの無料静的公開を維持する。

## 画面の導線

1. [制作画面](../editor.html)で問題を完成させる。標準盤面検証と全カギの入力に合格した時だけ「完成した問題を共有する」ボタンが有効になる。
2. ボタンを押すとURLを生成する。**リンクをコピー**、Web Share API対応端末では**送信する**、および**解く画面を確認**を表示する。
3. URL `index.html#p=1....` を受け取った人は、通常のプレイ画面でその問題を解ける。アカウントは不要。
4. 解答途中の進行状況は、受信者のブラウザ内で問題リンクごとに分離して保存する。従来の例題の保存キーは維持する。

## 仕組み

- `src/share/codec.mjs` に純粋な共有エンコード・デコード、検証、進捗キー関数を集約。
- 問題全体の重複情報は省き、**title・grid・語枠順のカギ・ルール**のみをコンパクト化する。UTF-8 → 固定12bit LZW → base64urlでURLフラグメントへ格納。
- 受信側では語枠・番号・解答を再計算し、共通 `validatePuzzle()` で必ず完全性を検証する。不正形式、無効なカギ、条件違反、過剰なサイズは拒否する。検証なしのHTML挿入はしない。
- レガシー `index.html` は生成時に `src/core/kana.mjs`、`src/core/puzzle.mjs`、`src/share/codec.mjs` のコードをインライン化し、ファイルURLでの例題表示の方式を維持。GitHub Pagesにも同じコードを配信する。
- 標準は縦横5〜15マスまで。URL上限を約6,500字に限定。長いカギで上限を超えた場合は短縮するか、既存のJSON保存を使う。
- プレイヤーの見た目と既存の答え合わせ・1文字ヒント・全解答表示・印刷を維持。行数・列数・問数だけ動的に設定する。

## セキュリティと制限

- **URLフラグメントは暗号化ではない**。共有したURLには答えが復号可能な形で入る。試験問題の正答の秘匿や認可・有効期限・閲覧履歴の記録には使えない。
- URLを知る人なら自由に再共有可能。氏名・個人情報・学校内部情報などを含めない。
- リンクを編集しても元の問題を更新しない。公開後の訂正や取り消しは、URLが内容そのものなので不可能。必要な場合は別URLを再発行する。
- 大きな問題や長い文章でURLが扱いにくい場合、将来的にサーバー側問題保管へ移行する。ただし初期版では課金・アカウント・データベースを必要としない。
- iPhone Safari上の共有シート、LINEへの貼付け、異なるiPhone/PCの解答保存はCI通過と別に実機確認する。

- GitHub ActionsのNodeテストと `npm run check` / `npm run build`。公開後は同一URLをブラウザから開き、盤面・問数・カギ・解答判定を確認する。
- 共有機能は「全体UX v4」を複雑にしないため、**制作画面の編集中は共有ボタンを無効化し、完成時だけ押せる**ようにする。
